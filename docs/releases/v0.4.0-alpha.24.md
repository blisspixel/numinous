# Numinous 0.4.0 alpha 24

Evidence and quality work, and one small change to what a kept creation offers.

## A clean machine, proved rather than assumed

The 0.6 exit asks that a clean machine on each supported system installs, plays,
saves state, and uninstalls from a signed or otherwise verifiable artifact. The
gates that existed covered most of that sentence and both said in their own
words that they did not cover this part. The install roundtrip packages its
archive on the runner that then installs it, which is convenient and is not
evidence: a machine cannot vouch for an artifact it produced.

A new gate begins where those stop. It never builds. It refuses to run on a
machine holding built faces, downloads the published archive and the published
soundtrack, proves the checksum and the keyless build-provenance attestation
bound to the tag commit before anything unpacks, and only then installs, plays a
room, writes player state, uninstalls, and requires every player-owned file to
survive byte-identical. It runs nightly on Linux, macOS, and Windows.

It reaches the "otherwise verifiable" half of that exit and says so. The
artifacts are not platform-signed or notarized, no window opens, no controller
is touched, and no sound is heard. The receipt carries those limits beside its
verdict.

## The gates that decide releases are now checked themselves

The Python scripts in `scripts/` decide whether a release ships, and they had no
linter and no type checker while the Rust beside them runs under Clippy with
warnings denied.

Linting now covers all fifty-eight. Strict typing covers a declared set that
starts at twenty-two and can only grow: a declared file that stops passing fails
the gate, and an undeclared file that already passes fails it too. That second
rule is the ratchet. Without it the list freezes on the day it was written.
Thirty-six scripts are not strict yet, and the gate reports that rather than
showing only its successes.

Retrofitting all of them at once was considered and rejected. Five hundred
hurried annotations would buy the appearance of rigor and none of it.

## A kept creation leads somewhere

Every surface that hands a caller something already says what to do with it: the
room doorways name a description call, the journal cue names the workspace.
Studio creations were the exception, so a kept capsule was an archive entry
rather than a door. Saving, opening, or forking now returns a pointer back to
forking, carrying the capsule the caller already holds.
