# Numinous 0.4.0 alpha 4

A second source-blind playtest of the published alpha 3 package reproduced every
finding of the first round as fixed and left one real trust failure. This
prerelease closes it, and sharpens two places where first contact still made a
player guess.

## A named call is never dropped

Seven rooms stage a wager before the explanation, and every one of them can also
reach that withheld beat by running its own experiment: land Times Tables on
four lobes, throw eight Buffon needles, drop four Galton waves. Five of the seven
already treated a wager named at that moment as the stronger commitment. Times
Tables and Buffon did not, and silently discarded it.

- A `place_wager` sent on the call that closes the four-lobe goal, or a
  `number_wager` sent once the needles have earned the beat, is now kept, shown
  back on `engineeredAha.wager`, and graded at consolidation.
- The caller can therefore tell that its own commitment landed, and the summon
  no longer opens the punchline through a path that never asked for a
  hypothesis.
- The withheld beat still hides `earn`, grade, truth, and punchline.
- Within one visit the first named call still owns it: a second wager is
  refused, and so is one sent after `aha_summon` has started the morph. Those
  two refusals are properties of a visit, so they are observable on the App and
  in the core state machine. The MCP face is stateless by design, where each
  call rebuilds the visit from its own arguments, so a later call carrying a
  different wager is a new first call rather than a second commitment.

## A doorway a structured client can see

- `list_rooms` returns `structuredContent.starters`, naming four rooms worth
  opening first. Compact discovery named those rooms only in prose, so a client
  that renders structured output still met 354 ids before touching a room.
- Every response mode still carries the complete typed catalog, so compact stays
  a presentation choice rather than a lossy one.

## A refusal that names its remedy

- A rejected Watch Agent start now says where a real pairing code comes from:
  a human running the App chooses Shared Play, and the one-use code it shows is
  the only code that starts a viewer. It also says plainly that unwatched play
  is the ordinary case.
- Other broadcast failures stay terse, because they fail on state a caller can
  already inspect.

## Known and open

The App draws and accepts its pointer wager band only during the prime beat, so
the superseding call is reachable there by its digit keys rather than by the
band. The App's visible-equals-clickable rule is intact and the keys are its
named-call affordance, so this is tracked as visual work behind the pinned
screen matrix rather than a silent drop.

## Release boundary

Stable `0.4.0` still requires the complete Understanding Alpha evidence gate.
This prerelease corrects the playable artifact. It does not claim a qualifying
cohort result, a learning result, or a consciousness measurement. The playtest
that produced it is formative external product evidence, described with its
boundary in `docs/PLAYTESTS.md`.

## Release evidence

- The complete Windows gate passes 3,576 all-target Rust cases, with three
  expensive diagnostics ignored by the ordinary suite. Measured coverage is
  95.28 percent by region and 95.28 percent by line under the documented
  hardware and event-loop exclusions.
- All 2,937 deterministic App screens pass the rendered QA matrix.
- Warning-denied Clippy, formatting, documentation, house style, installer
  self-tests, Agent Plugin validation, coverage, packaging, provenance, and
  three-operating-system CI remain required by the publication workflow.
