# Numinous 0.4.0 alpha 13

Both faces now open the same three doors.

Alpha 12 gave the App its first way to see the catalog. This release finishes
that work, so the door a player meets at the App is the door a mind meets over
the protocol: touch one astonishing thing, walk an authored route, or wander by
wing.

## Three doors, one threshold

The protocol face has offered three choices instead of a 355-room index since
the threshold landed. The App had none of them until a wing browser arrived, and
now it has all three, in the same order and opening onto the same rooms.

**Touch one astonishing thing** goes straight to the flagship. Which room that
is belongs to core rather than to either face, so if it ever changes, every
door moves together.

**Walk the Strange Loop** follows six rooms from a tiny local rule toward a
system that can point back at itself, in the walk's own authored order, and
carries that step's question into each room. That question is the first one the
App has ever had anywhere to put.

**Wander by wing** lists every wing the catalog has, keeps the arrows inside the
one chosen, and says how many rooms it holds, which is the first time the App
states that number out loud. Leaving is one entry at the bottom of the same
list, so nobody needs to know a key to get back to the whole cabinet.

A walk and a wing are different shapes and the code keeps them apart. A wing is
a place: a set of catalog indices walked in catalog order, wrapping inside
itself. A walk is a sequence: an order that is not the catalog's, tracking its
own position, because two steps of a walk could name the same room and a
catalog position cannot tell those apart.

## What the two faces share, and what they do not

The wing list, the walk, and the flagship's identity all live in core, so the
faces cannot drift onto different rooms or disagree about what the catalog
contains. A test proves the wings partition the catalog exactly: every room in
one wing, none missed, none named twice. Another walks every wing end to end and
requires it to close its loop. A third records why wing navigation needs a set
rather than a range, by asserting the catalog is not contiguous by wing, so if
that ever changes someone notices deliberately.

Each face still writes its own invitation, because a protocol sentence and a
menu label are not the same kind of writing and sharing the copy would make one
of them wrong.

## Boundaries this release keeps

Audio is still a sound sent rather than a sound heard. Stateless `play_room`
still accepts a second named wager as a new first wager. The packaged agentic
rounds play the protocol face headless and cannot reach a menu, so the App's
threshold is not evidence from that loop and is not claimed as such.
Understanding Alpha's exit remains open. Rounds and boundaries are in
`docs/PLAYTESTS.md`; gates are in `VERIFY.md`.
